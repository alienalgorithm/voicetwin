# 「轻度美化」可选版本 + 原声录音棚干净度：设计（2026-11-24，三路调研合并；研究用）

# VoiceTwin「轻度美化」可选版本，以及让原声版本尽量达到录音棚干净度的设计

这份是研究结论，没有改任何项目文件。代码位置都是我读过的：`voicetwin/synth/engine.py`、`voicetwin/webui/app.py`、`default_config.yaml`、`research/sv_benchmark/记录.md`。凡是标了「提议」「推算」「未核实」的数字，都需要实测确认。

## 0. 总原则（一句话版）

1. **原声版本（A，默认）不加任何会改变音色的处理。** 要它更干净，从三处下手：
   - 文字端：英文读音；
   - 选句：已有的挑候选；
   - 无损的增益和导出：只乘系数、真峰值、WAV。
2. **「轻度美化」版本（C）是可选的第三个版本。** 做法如下：
   - 处理链是**确定性的线性滤波加平滑增益**，全部有上下限；
   - EQ 的方向锚定在**她自己真实录音的长期平均频谱（LTAS）**上，不是通用的「录音棚曲线」；
   - **逐句处理，在拼接之前做**；
   - 每次都自动和原声配对比较「像你本人 %」、错字和频谱。超出测量误差就整篇减半强度，减到 0 就如实说「C 和原声一样」。
3. **最先进的生成式修复模型（Sidon v0.1）只当「参谋」用。** 让它算出一条频谱倾向，限幅后折进同一条线性 EQ，**它生成的波形永远不输出**。这样能借到它的「录音棚平衡」判断，又不可能改字、改时长、改音色细节。是否采用由打擂台的数据决定（第 5 节）。
4. **「英文更优美」靠音频后期做不到**（两份报告一致）。它放在生成之前（英文读音预检加词典）和挑候选上（发音评分），对 A 和 C 都有效（第 6 节）。

## 2. 「轻度美化」版本 C：处理链（顺序、工具、参数范围）

**输入**：`_make_variants` 已经推荐出的那个版本（A 或 B）的每句波形，记为 base，48 kHz、float32，在 `_render` 之前取。

**强度 s**：取值 {1, 0.5, 0.25, 0}，自动校准（第 4.1 节），界面上不放滑块。s=0 时输出必须和 base 完全相同（`np.array_equal`）。

**工具**：只用 numpy 和 scipy。VoiceTwin 本身已经依赖 `scipy>=1.8` 和 pyloudnorm，**不需要新增依赖，也没有 GPL 问题**。pedalboard 0.9.26 是 GPLv3，只在 CI 里拿来对照，不随包发布。

| 顺序 | 步骤 | 实现 | 有界参数（全部是提议，取自所引来源的范围，由校准决定 s） |
|---|---|---|---|
| S1+S2 | **一条静态线性 EQ**：高通和音色曲线合成一个最小相位 FIR | **1. 目标曲线**：`T(f) = clamp(C_her(f) + s·P(f), −2.5, +2.5) dB`，先平滑到 1/3 倍频程。80 Hz 以下和 16 kHz 以上用余弦过渡到 0 dB，叠加 2 阶 Butterworth 高通，fc = clamp(0.5 × 她 F0 的 p05, 60, 80) Hz。<br>**2. 锚点 C_her(f)**：C_her = LTAS_她真实录音 − LTAS_这篇生成（只取 silero-VAD 判为说话的帧，用 Welch 法，先对齐整体电平），限幅 ±1.5 dB。<br>**3. 倾向 P(f)**，s=1 时的取值：<br>- 「温暖/磁性」：低搁架 250 Hz，+1.5 dB，Q 0.7（范围 200–300 Hz、+0.5…+2.0 dB）；<br>- 「清楚」：峰值 3.2 kHz，+1.0 dB，Q 1.0（范围 2.5–4 kHz、+0.5…+1.5 dB）；<br>- 「空气感」：高搁架 11 kHz，+1.5 dB（范围 10–12 kHz、+0.5…+2.0 dB），只在她真实录音和生成两边的 LTAS 在该频段都高于底噪时才开。<br>300–600 Hz 的堆积不单独处理：C_her 已经会把它拉回她的水平。<br>**4. 滤波器设计**：先按目标幅度做频率采样，得到线性相位 FIR（4096 点，工程取值），再用 `scipy.signal.minimum_phase` 转成最小相位。<br>注意：homomorphic 方法默认得到的是原幅度响应的**平方根**（scipy 文档写明），所以设计时要用平方后的目标，或者在支持的版本里传 `half=False`。以单元测试实测的幅度响应为准 | 依据：<br>- Avid：温暖在 300–600 Hz，清晰度在 1.5–4.5 kHz，约 10 kHz 起可加平缓搁架；<br>- Shure：近讲效应「adds warmth and fullness」；<br>- Bücklein (JAES 1981)：提升比衰减更容易被听出来，所以提升都很小；<br>- LTAS 用于法庭说话人比对（Hughes et al. 2017）：往她自己的 LTAS 拉，按构造就是保身份的。<br>「磁性」没有找到经过验证的声学定义。吸引力研究指向 F0、共振峰和 HNR，这三样**刻意不动** |
| S3 | **去齿音**（动态，逐句） | 用 `sosfiltfilt` 分出 4–9 kHz 带（2 阶带通），其余部分 = x − band。检测量是 5 ms 帧的「齿音带 RMS / 全带 RMS」。<br>阈值 = **她本人真实录音这个比值的 p95**；最多压 −4 dB；attack 2 ms（范围 1–5），release 80 ms（范围 50–100）。<br>输出 = 其余部分 + g(t)·band。整句都没超阈值时直接返回原句，保证逐位相同 | iZotope：齿音「typically 4 to 9 kHz」。pedalboard 没有去齿音器，所以自己写 |
| S4 | **轻压缩**（逐句） | 前馈压缩，10 ms RMS 检测。比例：s ≤ 0.5 时 1.5:1，s = 1 时 2:1。<br>阈值 = 她本人说话帧电平相对整句的 p90，只压最响的部分；最大增益衰减硬限 3 dB；attack 20 ms，release 150 ms；**不加补偿增益**，由 S5 统一补。<br>整句没有任何衰减时返回原句 | iZotope：从 2:1 开始，只在最响处起作用。Sound On Sound：对说话哪怕轻压缩也「very obvious」，所以上限设得很低 |
| S5 | **电平** | 照搬 `_match_levels` 的做法：每句调回 base 这一句的说话响度（`speech_level_db`），再用 A2 的真峰值检查，超过 −1 dBTP 的这一句单独调低。**不用限幅器**（现有政策）。pedalboard 的 `Limiter` 有关不掉的自动补偿增益，本来也不能用 | 只乘系数 |
| — | 激励器 / 饱和 | **关闭** | 第 9 节 |

**顺序理由**：先做线性 EQ。「清楚」和「空气感」会抬高齿音，所以 EQ 后面接去齿音，再接压缩，最后统一电平。

**缓存**：每句旁边存 `.bt48000.<plan哈希>.wav`，仿照 `_denoised` 的 `.dn{sr}.wav`。哈希里包含 T(f)、s 和阈值，句子重新生成后缓存自动失效（同样比较修改时间）。

## 3. 逐句处理与绝对数字静音（怎么保证精确为 0）

1. 每句**拼接之前**单独处理：两边补 0.25 s 的 0，处理完裁回**原来的长度和原来的位置**。不允许有整体延迟：最小相位 FIR 和 IIR 都是因果的，`sosfiltfilt` 是零相位；验证要求互相关峰值的滞后为 0 个采样。
2. 原句里连续的精确 0（≥ 1 ms）处理后强制恢复为 0。
3. 然后照常交给 `_render`：每句做 4/8 ms 淡入淡出，放进全 0 的音轨，只乘增益。所以停顿、开头、结尾仍然是精确的 0。
4. 用 A3 的断言检查每个版本（A、B、C），检查对象是写出的 WAV（mp3 或 m4a 编码之前）。
5. **反例实测**（mastering 报告，合成信号）：同样的处理链如果在**拼好的整篇**上跑，52,800 个停顿采样里有 11,712 个变成非零，句尾拖 148 ms，最大到 −56.1 dBFS；事后硬切又会把尾巴切断。逐句做（补 0.25 s）的结果是非零停顿采样 0 个。

## 4. 自动把关：阈值都从实测噪声来

### 4.0 已有的实测噪声（`research/sv_benchmark/记录.md` 第 185–191 行，三个模型合并，均值 ± 标准差，单位是百分点）

| 处理 | 像你本人 % 的变化 |
|---|---|
| 音量放到最大 | −0.1 ± 0.9 |
| 去杂音 + 绝对静音 | −2.5 ± 3.1 |
| 停顿改成绝对静音 | −2.6 ± 4.3 |
| 白噪声 20 dB | −7.7 ± 7.0 |
| 只有 1.5 s 人声 | −13.3 ± 10.8 |

EQ 和压缩**从来没测过**，第 4.1 节就是去测它。

### 4.1 一次性校准（每个新模型做一次）

放在已有的 `select.py::prepare_identical`（「第一次用新模型先做一次准备」）里，用的是同一份 100% 锚点：她没参加训练的真实录音验证集。

1. **空白对照 D_null**：把每段录音的音量改一下（和 §10「音量放到最大」同法）再打分，得到配对差的分布，记录 μ_null 和 σ_null。ASR 和 F0 的抖动也这样量。
2. **处理链**：对 s = 1、0.5、0.25 各跑一遍，得到配对差 Δ_s。
3. **验收规则**：mean(Δ_s) ≥ μ_null − 2·σ_null/√n，也就是和单纯改音量在统计上分不开（单侧约 95%）。取通过的最大 s 记为 s*。都不通过时 s* = 0，C 不提供。
4. 结果写入模型旁边的 `beautify_calib.json`，报告里列出实测值。

### 4.2 每篇、每句：C 对 base 配对检查（关卡表）

| 关卡 | 规则 | 不通过怎么办 |
|---|---|---|
| G1 身份（整篇） | 人声 ≥ 2 s 的句子上，mean(Δ) ≥ μ_null − 2·σ_null/√n | 整篇 s 减半重做，最低到 0；只重算处理和打分，有缓存 |
| G2 身份（逐句） | Δ_i ≥ μ_null − z(1−0.05/N)·σ_null（Bonferroni 校正，使单纯改音量的整篇有约 95% 概率全部通过）；另外 pct_C,i ≥ 现有的 `min_pct`。<br>**推算**：按现有 μ=−0.1、σ=0.9、N=100 句，阈值约 −3.1 个百分点，要在新模型上重测。<br>人声 < 2 s 的句子不做 SV 关卡（实测 −13.3 ± 10.8，太不可靠），只查 G6–G9 | 这一句关掉 S3 和 S4，只保留全篇一致的静态 EQ。还不过就按 G1 整篇减半。**不允许逐句开关 EQ**，否则句与句之间音色会跳 |

| G8 底噪和伪影 | 说话部分底噪 `speech_noise_floor_db` ≤ −60 dBFS（和 `DENOISE_FLOOR_DB` 一致；ACX 也用 −60，via search）；base 本来就高于 −60 的句子，要求不高于 base。真峰值 ≤ −1 dBTP | 关掉这一句的 S4（压缩加补偿会抬高底噪） |

## 6. 「英文更优美」：不靠后期，A 和 C 都受益

1. **第一阶段**：`英文读音预检`。用 V5 运行环境自带的 english.py 跑讲稿里每段英文，列出下面这些情况：
   - 全大写词，会被逐字母读；
   - 带点的缩写：Dr.、Mr.、U.S.、No.；
   - 数字加 s，例如 1990s；
   - 英文里的 ; 和 :；
   - 词典外、靠神经网络猜读音的词；
   - CMU 词典里有多个读音、但只取第一个的词：lead、live、wind、tear；
   - g2p_en 的同形异义词（object、read 的条目本身是错的）；
   - 单独提到的功能词，强读还是弱读。

   **老师词典**存在声音文件夹里，格式是「词 → 带重音的 ARPAbet」。运行时打补丁到 `text.english._g2p.cmu`，训练（`get_text_mixed.py`）和推理（用一个小启动器经 runpy 跑 api_v2）都用同一份。词典哈希加进缓存键（engine.py 第 866–877 行附近），词典改了要重启服务；训练标签变了要重训。

   **只改送给引擎的那份文字**：; 和 : 改成 ","，Dr. 改成 Doctor，1990s 改成 nineteen-nineties。字幕和 CER 的参考文字保持原样。
2. **第二阶段**：发音评分作为同分时的次序依据。
   - 模型：facebook/wav2vec2-xlsr-53-espeak-cv-ft（Apache-2.0，按 HF 页面，via search），按论文自己实现无切分的 CTC GOP（原仓库**没有 LICENSE**，不能抄）。

## 7. 老师在界面上看到什么（最少改动）

**生成页**，「质量」下面加一个勾选框，只在「完美」和「一模一样」档显示（这两档本来就在做多个版本），默认不勾：

> ☐ 同时做一个「轻度美化」版本（可选）
> 说明：在你的原声上做很轻的润色：声音稍微更温暖、更清楚，齿音更柔和。不改音调、不改语速、不换声音。做完会自动检查「像你本人 %」和错字：比测量误差降得多、或者错字增加了，就自动减轻或者不用。句子之间仍然是完全的数字静音。原声版本照常生成，不受影响。

**结果区**：

- 在现有的 A 和 B 播放器旁边加第三个播放器「版本 C：轻度美化」。
- 「最终使用哪个版本」里加 ("版本 C：轻度美化", "轻度美化")，只有 C 通过检查时才出现。
- 推荐（⭐）仍然只在 A 和 B 之间按「更像你」来定。C 不参与推荐，但会如实写出它的数字。
- 文件名沿用现有规则，例如 `…_轻度美化_V5.wav`。`workflows.py` 第 1246 行是精确匹配名字，不冲突。

示例文字（数字都是实测后填入）：

- 「版本 C 轻度美化（润色强度：一半）：像你本人 97.8%，原声 98.3%，相差 0.5%，在测量误差（±x%）以内；错字没有增加；第 4、9 句太短（人声不到 2 秒），只做了和全篇一样的音色润色，没有单独比像不像。」
- 「这次轻度美化没通过检查（第 12 句像你本人比原声低了 6.0%，超过测量误差），已经自动减轻到四分之一。」

## 8. 怎么测

**GitHub（CPU，不下载模型，现有 `tests.yml` 在 ubuntu 和 windows 上跑）**，新增 `tests/test_beautify.py`。每条规则配一个坏样本和一个好样本：

1. s = 0 时逐位相同（好样本）。动态处理没触发的句子也逐位相同。
2. 用合成的讲课音轨走 C：
   - 好样本：停顿里非零采样 = 0，每句首尾 = 0，长度相同，互相关滞后 = 0。
   - 坏样本：同一条链在整篇上跑，**必须**被 G9 抓到。
3. FIR 实测幅度响应：80 Hz–16 kHz 以内 \|T\| ≤ 2.5 dB，以外是 0 dB（误差要写进测试）。最小相位：冲激响应在主峰之前没有能量。专门测一下 `minimum_phase` 的「平方根」陷阱。
4. 真峰值表：fs/4 正弦、相位 45° 时，真峰值 = 采样峰值 + 3.01 dB（数学事实）。
5. 压缩的增益衰减 ≤ 3 dB，去齿音的衰减 ≤ 4 dB。
6. 关卡单元测试（用假打分器）：
   - 坏样本必须被拒：Δ = −10 个百分点、CER 上升、+12 dB 搁架（G6）、8 kHz 以上能量超出 p95（G7）、20 dB 白噪声（G8）、移调一个半音（G4）。
   - 好样本必须通过：只改音量。
7. 界面文字测试，仿照 `tests/test_identical_tier.py`：说明里不写没实测过的说法。

**GitHub 新工作流 `beautify-calib.yml`**（workflow_dispatch，并在 `claude/**` 分支的相关路径变化时触发；ubuntu，CPU）：

1. 下载 sv-models-1 Release，以及她的真实录音。CLAUDE.md 第 8 条：老师 11-24 同意讲课录音可以放；下载地址列在 `research/轻度美化/录音.txt`，做法同 `transcribe.yml`。
2. 量 D_null，跑 s ∈ {1, 0.5, 0.25}，记录 Δ像你本人、CER/WER、G6/G7 和 PQ/UTMOSv2（评分模型只在 CI 里下载）。
3. 第二阶段加 X1 和 X2。CPU 耗时未知，太慢就只取子集。
4. 拿 `gsv-v5-real` 生成的音频（程序合成的声音）跑整篇拼接，检查静音。
5. 结果提交到 `research/轻度美化/结果/`。

开发机连不上 Hugging Face；GitHub runner 能不能连**未核实**，第一次运行时确认。

## 9. 不采用的方案和原因

| 方案 | 原因 |
|---|---|
| 生成式修复直接输出波形（Sidon、Resemble Enhance、VoiceFixer） | 会重建整条波形，时间和相位都不再是原来的，有幻觉风险，MOS 类分数又查不出来。<br>- VoiceFixer：Hi-ResLDM 论文说它「altering the speaker's pitch and tone」（via search）；<br>- Resemble：固定 44.1 kHz，依赖 deepspeed（Windows 上难装），PyPI 最后一版是 2024-01；<br>- Sidon：只作为 X2 的参谋 |
| 生成式输出和原声在时域按干湿比混合 | 时间和相位对不上，会产生梳状滤波 |
| matchering 2.0.6 | 内部 44.1 kHz（配置里自己写其他采样率「not tested」）；修正比例没有上限；4096 点线性相位 FIR 在每个起音前预振约 46 ms；为 M/S 立体声设计；GPLv3。思路已经用有界、单声道、只取说话帧的方式复用在 C_her 里 |
| 随包发布 pedalboard | GPLv3，打进 MIT 的 zip 会带来分发义务；`Limiter` 有关不掉的补偿增益；高通只有 1 阶。scipy 能做同样的事 |
| 激励器 / 饱和 / 「加磁性」的谐波 | 非线性；找不到针对说话的可靠参数依据；主要改的是 8 kHz 以上，SV 和 ASR 都看不到，没法自动把关 |
| 移调或移共振峰来「更磁性」 | F0 和共振峰正是身份线索，直接违背「必须是她」 |
| 整篇做 EQ、压缩、限幅或 loudnorm | 实测会破坏数字静音（第 3 节）；loudnorm 做不了线性模式时会退回动态模式，类似自动增益 |
| 砖墙限幅器 | 现有政策是只调增益；压缩已经限住了峰值 |
| 口音转换（Vevo、FAC-FACodec、activation steering） | Vevo 权重 cc-by-nc-4.0，和 B 站盈利冲突；FAC-FACodec 没找到代码；activation steering 基于 Qwen3-TTS，代码未确认。它们都把口音往「标准美式」推，会牺牲身份 |
| StuPASE/PASE | 只有 16 kHz，会丢掉 48 kHz 的高频 |
| A2SB | NVIDIA 许可，仅限非商业 |
| SGMSE+ | 为带噪输入设计，多步采样很慢，权重许可未核实 |
| MossFormer2_SE_48K | LSD 1.86，比带噪输入的 1.45 还差 |
| Hi-ResLDM、VoiceBridge、AuraSE、NovaSR、FlashSR | 没有可用的代码或权重（sony/Hi-ResLDM 2026-11-24 返回 404），或者只有自报结果 |
| NISQA 当关卡 | 权重是 CC BY-NC-SA 4.0 |
| Adobe Podcast、NVIDIA Maxine | 闭源；Adobe 要上传她的声音；Maxine 要 AI Enterprise 许可，RTX 50 支持未核实 |
| 对训练素材做生成式修复 | 模型学到的会是修复器的音色，而 100% 锚点是她本人录音；她的素材本来就接近录音棚质量（时间线 03:30「我的课基本就是录音棚音质」） |
| 频带扩展无条件开启 | 没有测出高频不足之前不做（A6） |

## 10. 未核实和风险清单

- EQ 和压缩对「像你本人 %」的影响从没测过，第 4.1 节会测。
- G2 的约 −3.1 个百分点只是按旧数据推算的。
- 所有 S1–S4 参数都是有界的提议，需要实测确认。
- DeepFilterNet 0.5.6 和 Sidon 在 Windows、RTX 50、torch 版本下的兼容性。
- Audiobox Aesthetics 和 UTMOSv2 的模型大小、输入采样率（如果它们也是 16 kHz，同样看不到 8 kHz 以上），以及能不能装在老师电脑上。
- V5 输出在 12 kHz 以上有没有真实内容（A6）。
- 打 GOP 补丁对 V5 实际读音的效果，以及 GOP 在同一句的候选之间排序是否可靠。
- 老师电脑上的 CPU 和 GPU 耗时，没测。
