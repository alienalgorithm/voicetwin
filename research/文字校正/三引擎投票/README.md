# 三个识别引擎投票（11-24）：faster-whisper + FunASR + SenseVoice

## 为什么做

老师新录的 26 分钟课（204 句）由两路独立核对出了定稿（`research/新录音转录/核对结果/逐句定稿.json`），
每句都有三个识别引擎各自听到的文字。拿定稿当标准答案量字错率（标点、空格、大小写不算），
三个引擎各错各的：

| | 字错率 | 有错的句子（/204） |
|---|---|---|
| faster-whisper（程序的主识别） | 3.70% | 103 |
| FunASR paraformer（程序原来的「查错字」第二个引擎） | 2.82% | 81 |
| SenseVoiceSmall | 2.56% | 87 |
| 程序原来的结果（whisper + 📝 一键全部文字校正，真跑的） | 3.52% | 100 |

程序原来只用 FunASR 对比：不一样的地方标红给建议，但「一键全部文字校正」不敢采用（不知道两个引擎哪个对），
所以一键校正以后几乎没变（3.70% → 3.52%）。有了第三个引擎，两个引擎听到的一样就能定下来。

## 怎么投（`voicetwin/data/asr_vote.py`，纯文字处理，不用模型）

1. 三段文字按字对齐（汉字一个字一个、英文一个词一个、数字按数值、标点不算），以现在的文字（faster-whisper）为准，
   一处一处比；
2. **另外两个引擎听到的一模一样、和现在的文字不一样 → 有把握的建议**，一键校正直接采用。英文也一样；
3. 只有一个引擎不一样：两票对一票，现在的文字赢，投票不给建议（FunASR 不一样的地方照旧标红，老师听录音决定）。
   所以英文只要另外两个引擎拼得不完全一样，就保留 faster-whisper 的拼法（FunASR、SenseVoice 常把 kills 写成
   chaols、that 写成 net / dead）；
4. **例外：少数那个引擎的写法正好凑成了标准库里的语法术语**（`grammar_terms.txt`，至少 3 个字，比如
   「名词型从句」→「名词性从句」）→ 按术语改，也算有把握；
5. 读音一样、两种写法都常见的字（他 / 它、地 / 的、在 / 再、做 / 作、哪 / 那）不改；
6. 一处超过 6 个字 / 词：只给建议，不自动采用；另一个引擎整句和现在的文字对不上一半：它这一句不参加投票。

程序里怎么接（`voicetwin/data/proofcheck.py`、`transcript_fix.py`）：
- 主识别是 faster-whisper、对比用 FunASR 时，查错字再用 SenseVoiceSmall（`iic/SenseVoiceSmall`，FunASR 工具包，
  第一次用时从 ModelScope 下载；V5 整合包的 funasr 1.3.22 带它）把中文片段听一遍；结果和 FunASR 一样存缓存；
- 投票有把握的地方：标红、说明写「另外两个识别引擎都听成「……」」，建议里按投票的改，只按这些改出来的整句存在
  `suspect["vote_alt"]`；「📝 一键全部文字校正」时这几处算有把握、直接采用（和母本对不上的照旧以母本为准）；
  标准库也给了同样改法但分量不够的，有了投票也算有把握；
- SenseVoice 装不上、下载不下来、某一条出错：只是不投票，照旧和 FunASR 对比，说明里写清楚；
- 不想要可以在设置里写 `prepare.proofcheck_vote: off`。

## 实测结果（`实测.py`，结果在 `实测结果.txt`）

| | 字错率 | 有错的句子 | 错的字 |
|---|---|---|---|
| 程序原来（真跑的） | 3.52% | 100 | 361 |
| 投票（纯文字，只改有把握的） | **1.61%** | **49** | 165 |
| 走一遍程序、投票关掉（假的引擎按记下的文字回答） | 3.52% | 100 | 361 |
| 走一遍程序、投票打开 | **1.65%** | **50** | 169 |

- 「投票关掉」和真跑的结果一字不差（3.52%、100 句），说明这个走一遍程序的办法和老师电脑上一样；
- 投票打开以后，一键校正直接改了 136 处，还标红「可能有错」的句子从 89 句降到 41 句（老师要听的少了一半多）；
- 主会话用「以 FunASR 为底、另外两个一样就换」的简单投票量过 2.06% / 54 句；现在以 faster-whisper 为底
  （它的英文最准）加上语法术语那一条，更好。

### 每条规矩是怎么定的（都在这 204 句上量过）

- **英文也按两票对一票**：另外两个引擎把英文拼得一模一样、和 faster-whisper 不一样的地方，按投票改
  一共改对 75 个字、改错 9 个字（what → word 两处、are → a、NAT → net）。试过「faster-whisper 写的是老师母本里
  出现过的英文词就不改」：water → what、that → does 这些改对的也被挡住，反而更差，没用；
- **他 / 它、地 / 的、在 / 再不改**：按投票改，对的 7 处、错的 6 处，等于瞎猜；
- **语法术语那一条**：改了 32 个字，一个都没改错；
- 几个数（另一个引擎至少多像才参加：0.3 ~ 0.7；一处最多几个字算有把握：3 ~ 100；挨着的不一样的地方合不合成一处）
  怎么换结果都一样，不是凑出来的。

### 剩下的错（投票也改不了）

- 三个引擎都没听对的英文：whether（banner / venner / vendor）、that（net / dead，三个里有两个错成一样）；
- 两个引擎一起错成一样：出现在 → 出现了、同位语 → 同语、酒保 → 九保；
- 只有一个引擎对、又凑不成语法术语的（比如只有 SenseVoice 听对的 kills）：照旧标红，老师听录音决定。

## 运行

```
PYTHONPATH=. python research/文字校正/三引擎投票/实测.py
```
